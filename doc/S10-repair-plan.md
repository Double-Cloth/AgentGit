# S10 缩减、独立确认和 Repair Lab 实施计划

依据设计文档 5B.4、实施方案 S10、4.3 和 6.2。完整目标继续包括 S11 及 S12-A/B/C/D。S8 保留集注入点 Top-3 4/8 未达标，人工审阅和 S6/D1 独立 Windows/原生专项按用户指示暂缓；不能凭本阶段的工程推进宣称这些前置已经完成或定位优势成立。

## 交付顺序

1. 冻结逐补丁删除协议和证据契约，保证非单调场景在每次成功删除后重新检验剩余单项。确定性、完整的规定删除测试才可给出相应原子补丁语法下的 1-minimal；随机模型只报告经验缩减，未完成或预算不足保持未证明。字段级缩减另用预定义变换，不能据原子删除证明字段、文本编辑或全局最小。
2. 冻结最终候选、独立样本身份与确认判定。先锁定候选，才打开确认响应；默认六个独立确认试验、四个固定回归任务。筛选/缩减结果不能顶替确认。对确认失败后重新选补丁，必须使用新的独立保留样本，不能重用已经打开的同一池。
3. 在现有 Job/Run、Replay、S7 干预与预算台账上接入耐久缩减/确认编排。所有阶段共用最初搜索的次数、调用、费用和墙钟上限，取消、租约、重启及未知效果保持原有约束。新 DDL 使用新迁移及冻结快照，不能改写历史定义、先前停止决定或旧迁移。
4. 锁定候选后的完整确认、回归、原始证据、成本和适用范围进入修复提案。筛选通过、确认门槛通过、回归通过及安全是不同事实。受控合成成功只能称 `verified_under_fixture`；真实模型结果单列经验验证和分布/时间/小样本限制。
5. 接入 API/CLI、精确 Diff 与批准/拒绝事务，绑定提案摘要和预期 Agent 配置版本。批准仅创建配置新版本，不启动工具、不改旧配置；工具观测补丁只能保存为实验，不能采纳到正式配置。再实现遵守 DESIGN.md 的 Electron Repair Lab、IPC 和断连重开核对。
6. 建立 30 例、任务层 20/10 划分和四个同预算自动基线，冻结模型、策略和输入后执行。报告全部成功/失败/无解/伪修复，开发集 12 个声明可修复例的 10/12 目标如实计分；保留集不根据已见结果调参。最后更新 Windows 分发候选并完成适用包内复验，保留未提供的原生/独立环境项目。

## 两层样本隔离

任务层按五类 10/8/4/4/4 分配单点、联合、观测伪修复、空间无解和副作用约束；20/10 分别为 6/4、6/2、3/1、3/1、2/2。同一模板轻微改写不得跨任务 split。已见的 S8 数据不用于新的修复保留集调参，旧 S9 工程 fixture 也不直接冒充完整 30 例评估。

每项任务另有 screen/reduce 响应池、confirm 独立响应池和固定 regression 样本。池的内容摘要和角色先冻结；确认样本必须与筛选/缩减的响应内容身份分离，不能只换名字或 split 标签。试验还必须具有不同 trial/Run/结果引用，且绑定同一最终候选；这些身份检查是必要工程约束，不单独证明统计独立性。

`response_set_ref` 表示包含真实来源及冻结生成条件的完整响应样本包身份，不能把 role/split 标签本身计入生成新的来源身份。独立生成的样本可以得到相同文本；不能为了让文本摘要不同而筛掉相同输出、改变分布或替保留样本挑选有利结果。持久发布必须核验包的真实来源和预注册生成条件，纯摘要相异不能单独证明独立采样。

公共确认入口不能接受用户上传的 passed 字段作为事实。持久服务从实际 Job 终态、固定验收器、CAS 归属及原始用量生成内核输入；纯判定模块仅处理已经核验的有界证据，不具备执行、审批或打开确认响应的权限。

## 缩减与统计边界

固定顺序逐项删除；某次删除达标后接受更小候选，并从新候选重新开始所有剩余单项的删除。旧集合下的失败不能证明新集合下仍必要。每个变更都需要新的独立 trial，不能把 S9 单点失败记录直接充当 S10 删除测试。S10-T01 的 A+B+C 用来检验通用缩减内核；S9 公共搜索的默认深度二保持，不借测试扩大默认搜索空间。

确认默认必须完成六次、至少五次硬断言通过、安全零违规，再完成四项固定回归；未运行、预算/未知、非确定执行错误和不完整验收都保留。5/6 是经验门槛，不要求区间下界达到 80%，也不据此证明线上稳定。95% Wilson 双侧区间用十进制运算和十进制字符串输出，n=0 无区间，不添加数值依赖。公式依据 [NIST/SEMATECH 7.2.4.1](https://itl.nist.gov/div898/handbook/prc/section2/prc241.htm)，不是 Wald 或精确二项区间。

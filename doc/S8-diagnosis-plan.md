# S8 行为对齐与故障候选定位方案

依据设计文档 5B.2 和实施方案 S8。S7 自身本机功能/包内退出证据已归档；S6/D1 的环境与原生前置继续保留待补，不以本阶段开发修改其验收状态。先接通只读行为证据，再做候选与实验，不把静态分歧当作已证实根因。

## 实施顺序与完整范围

1. 增加严格类型化事件引用、依赖图和行为对齐。读取当前项目既有事件、版本及 CAS，校验事件归属、内容和因果引用；使用共同版本祖先、logical step、occurrence、工具签名和规范请求，不使用到达时间配对。重复身份不能确定时保留歧义。首个可见分歧为 DAG 上的最小前沿，可以有多个。
2. 从显式 caused_by、同 occurrence 的调用结果、已核验的计划依赖和决策上下文建立可解释边。边保留来源种类；缺失、跨范围、缺少已承诺内容等分别处理。越权引用拒绝，不读取外部对象补齐证据，不凭事件相邻推导因果。
3. 在排序实现/调参之前冻结 20 个可控故障样例、12/8 划分和标注说明；覆盖错误检索、空响应、Schema 变化、超时、计划遗漏、冲突记忆等。标注来源和审阅状态明确记录；自动编写的标签不冒充已经完成的人工标注。保留集不用于规则调参。
4. 候选规则按失败依赖路径、距离、首个可见分歧及歧义排序，不引入模型根因分数。分别保留注入位置、第一处可见错误和可修复决策点；无成功参考时从硬断言提取候选，说明证据不足。
5. 在显式预算内复用 S7 单变量干预和独立 trial 获取效果证据。未运行、预算不足、无法绑定合法干预或结果未知时保留 static_only，不伪造改善率。所有失败和未定位样例都进入 Top-1/Top-3、步骤/调用/成本与时间首异常基线。
6. 生成可点击 Debug Report，并在现有 Diff/Timeline 接入候选、事件跳转、对齐歧义和实验设置/结果。遵守 DESIGN，不新增导航或依赖。S8-T05 的 6/8 是待测目标；未达标仍明确记录能力边界，按实施方案的显式全候选降级规则进入后续工程验证。

## 首个增量

本轮先实现第 1–2 步的只读基础：纯依赖图/对齐、带归属核验的读取服务和 API/CLI。完整读取有事件/边/字节上限，超过即失败，不将前缀当作完整轨迹。模型、工具、容器、数据库迁移和修改 Job 均不由该读取流程触发。

输出区分匹配、属性变化、仅单侧出现、重复身份歧义和缺失证据。时间戳、数据库事件 ID、到达顺序只用于寻址/展示，不能作为匹配或消歧依据。无共同版本祖先时明确不具备比较上下文。此增量不宣称完成候选排序、20 例评估、干预验证或 S8 整体验收。

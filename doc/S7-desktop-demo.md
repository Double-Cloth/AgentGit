# S7 桌面受控实验操作

适用 [Windows 0.1.4 候选](acceptance/S7-package-014.md)。先按 [D1 指南](D1-desktop-demo.md)准备回环 API、独立 Worker、PostgreSQL、固定镜像和身份，完成一次离线五工具来源 Run。代码、依赖和语料在实验期间保持冻结；当前阶段使用离线 Mock，真实供应商冒烟单列。

## Live A/B

1. 在来源 Timeline 选择目标行为之前的安全检查点，点击“从所选检查点分支”，再选“受控 A/B 实验”。核对来源 Run、完整起点摘要、来源模型和预算。起点后应有待比较的剩余计划；从已完成终态仅复核历史结果，不能说明后来没有执行的 Prompt 条件产生了效果。
2. 选择 screen/confirm/regression split，显式“冻结共同验收器”。展开固定输入查看语料、时间、规则、代码和依赖摘要。冻结后来源锁定；“重新选择来源”会清除旧条件、预算、validator 和调用选择。
3. 设置 A/B 名称与条件。每组可沿用来源、提供完整 Prompt、完整计划 JSON 或填写有序干预 UUID；默认各 5 次，共 10 trial。两个沿用来源组只比较同条件重复结果。Prompt 是完整值，可通过只读上下文“复制来源 Prompt 到 B”后修改；计划仍须通过后端完整契约与已完成节点检查。
4. 选择 Live，核对每 trial 共同预算。外部模型须另填 USD 上限，授权合计按两组次数计算；界面估价与预留有明确来源，供应商账单保持未知。点击一次“提交 A/B 实验”，保存完整 Experiment UUID；若结果未知，继续原请求/原键，界面会保留该请求供核对。
5. 查看 manifest、A/B 全部预定样本的通过率和未完成数，切换“全部消耗/已验收完整试验”。均值/方差标出样本、缺失和单位，近似值有 `≈`。trial 的时间线与控制使用当前 Run；暂停、取消在 Worker 安全点落实，恢复前核对实际状态。

关闭桌面后后端继续。重开选同一项目，在实验列表或 UUID 中查询，查询不排队新任务。断连显示上次已确认报告和明确错误；旧代码验收器不兼容时按错误处理，保持原 manifest/引用，不重判历史。

## Hybrid 与工具响应干预

1. 在已冻结共同来源下，选择 Hybrid，填写同一来源的录制范围终点。右侧“只读调用与干预”可浏览调用开始事件；填写的是正整数事件 ID，事件 seq 与调用 UUID 是另外的标识。
2. 点击“读取调用上下文”，核对 source_call_id、完整请求/签名、目标 checkpoint 和前置条件。只有受控只读 corpus_search/source_read 能加入 Hybrid 调用集合。选择 stop 或固定 fixture 的未命中策略；参数或签名变化会按该策略处理。
3. 如需 TOOL_RESPONSE_PATCH，在高级区域填写同项目已完整录制且同参数/同签名的替换调用 UUID 及理由，点击“冻结工具响应补丁”，取得不可变干预 ID 后显式“加入 B 组干预”。B 已使用直接 Prompt/计划时，先明确改选条件类型再加入；类型化干预须与当前共同起点/验收器匹配。
4. 提交后逐 trial 查看 recorded、fixture、synthetic 和 miss。synthetic observation 始终带 test_only；即使补丁使用相同字节，来源仍标为合成。成功只证明该冻结试验条件下通过验收，后续真实修复仍需独立复测与审阅。

已有 PROMPT_PATCH/PLAN_PATCH ID 可从 [API/CLI 干预入口](API.md#类型化干预)创建，再按顺序填入分组。响应补丁只引用录制，不接收任意上传的响应、URL 或宿主路径。未到达选定依赖、预算耗尽、取消和未知结果均需按实际状态阅读，不算作通过。

完整实测、退出核对及尚待补验边界见 [S7 总矩阵](acceptance/S7-gates.md)。S6 的独立用户、原生保存、DPI、禁止外网和依赖缺失要求仍保留。

## 冻结的事实

`RepairValidationPoolService.submit` 只接受尚未被首次领取、无试验且未取消的 S9 搜索，以及四个明确的回归 `source_run_id/from_commit`。服务从同项目实际 Run/检查点、冻结任务、语料、配置与当前代码/依赖生成六张 confirm 和四张 regression 采样票据，并冻结固定规则验收器。回归须有四个不同任务输入，不能复制原确认任务、重复不同 Run 下的同一任务，或使用其他项目来源。配置/模型/权限保持原授权；起点必须允许新的模型决策，不能重验已经完成的输出。

这是在线重新调用协议 `fresh_model_invocations/v1`。票据含服务生成的 generation ID、任务/验收器/语料、模型条件、来源状态/环境/配置和代码/依赖摘要，内容不含 role，也不含已生成响应；阶段由不可变样本映射给出。`response_set_ref` 在这个协议下指冻结的生成条件身份，后续实际调用和结果须另有原始来源证据绑定。它不是历史响应包，也不能凭不同 UUID 或摘要证明独立抽样。相同采样条件允许生成相同文本，不按输出去重或挑选有利结果。

预注册发生在筛选首次领取前，准备和提交分开；提交时再次锁定搜索控制行核对。没有预注册的旧搜索不能在看到筛选结果后临时补造独立保留池，应使用新的预注册搜索。历史搜索、停止决定和迁移保持原定义，旧代码池只读保留。

## 开启和预算

`open` 只允许同一搜索已锁定且未取消的最终候选，沿用最初搜索墙钟、次数、实际调用/字节/费用与未决预留。开启前检查完整六次确认、四次回归的冻结额度和最坏资源；不足返回 `opened=false` 及明确预算原因，不打开池、不扩大授权、不记作试验通过。

开启事务同时写入唯一 suite→study 绑定、最终锁摘要、完整 `RepairValidationPlan`、开启审计及 `validation_ready` 控制状态。每个 suite 只能打开一次，同 study 重试返回原绑定，同键异参拒绝。取消先提交会阻止开启；开启后取消保留已打开的历史绑定，重试原请求不能恢复任务。注册及开启的提交前回滚、提交后丢失确认均须复用既有身份，不能留下半套样本/计划或重复事件。

`validation_ready` 只表示预注册条件已打开且可交给下一阶段，`execution_status=not_started`。纯判定器对当前零确认/零回归证据返回 `needs_review`、`production_eligible=false`。尚无实际独立样本成功数或效果结论；后续执行必须核对每张票据的新 Job/Run、真实调用、固定验收与实际计量，未知不能补零。

新迁移 `0020_repair_validation_pools` 增加 suites、samples、openings 三张不可变表；数据库约束首次领取前注册、样本归属、模型决策起点的 Run/Commit 关系、候选锁后开启、十项样本完整、唯一池使用及状态/审计原子关系。`schema_s10_pools.py` 只在新快照扩展控制状态，未改写历史快照或旧迁移。仅测试自建 Schema 迁移，业务库未迁移。

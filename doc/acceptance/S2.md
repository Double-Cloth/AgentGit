## 实现与不变量

CAS 使用同卷临时文件、文件 fsync、硬链接 create-if-absent 发布，不以可覆盖目标的 replace 实现去重。读取核验类型域、长度上限与 SHA-256；已存在但损坏的文件拒绝覆盖。拒绝 CAS 根/分片目录链接和联接。临时文件和未入索引文件只扫描，不自动清理。

数据库增加项目、对象、引用、分支、Commit/父关系、Run、事件、Snapshot、Run/Commit 关联、产物和调用记录表。复合外键约束同项目归属；数据库触发器拒绝历史 UPDATE/DELETE、已发布节点补写 parent 和父关系环。历史仍为单父，不支持 Merge。

提交先发布完整 state、environment、事件清单、事件载荷和产物，再在短事务中锁定 Run/分支、重查序号及 expected HEAD/version、插入全部引用和 Snapshot，并 CAS 推进 HEAD。调用记录的细粒度事件可先耐久追加，下一次状态提交会收录全部尚未归档的事件。保留事务内 writer guard 供 S4 的租约/fencing 校验接入，本阶段尚无 Worker 租约。

恢复验证 Commit 内容与索引、父关系、环境及当前项目登记的输入、事件范围/连续性/载荷、完整 state 与产物清单。没有只凭 hash 下载任意项目对象的业务接口。相同内容可物理去重，读取经所属 Commit/Artifact 约束。

## 限制与后续入口

- 验收是在 Windows 主机、NTFS CAS 和真实 Linux PostgreSQL 容器完成；Linux CI 已配置但尚未执行，不宣称已跨平台实测。崩溃测试验证进程终止，不代表存储硬件断电测试。
- GC 仅识别未入索引对象/临时文件，保守保留全部已入索引对象；不提供实际删除接口，尚未做生产备份恢复。审批预留通过引用表保留，不冒充已实现 S4 Approval。
- Run/调用表与 writer guard 是后续恢复的基础；持久化 Job、审批、结果不明核对、活动写者绑定和真正 fencing 留在 S4。
- `commit` 的 artifacts 参数表示本次完整文件清单；空清单表示该状态无产物。S3 Runtime 必须携带需要保留的全部文件，不能将其当增量 patch。
- `schema_s2.py` 是已验收迁移快照，后续只通过新迁移扩展，不能为新字段改写旧 revision 的 Schema 构造器。
- 保留 S1 已记录的 Starlette/httpx 弃用提示，没有隐藏警告或增加未要求依赖。

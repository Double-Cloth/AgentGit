# S9 自动搜索循环与模板入口

依据设计文档 5B.4、实施方案 S9、6.2；这是有界搜索的工程验收记录。用户已允许稍后审阅 S8 人工标签并暂缓独立 Windows 环境验收。S8 保留集注入点 Top-3 仍为 4/8，未达到 6/8；本轮没有读取保留集、调整排名或宣称定位优势。

## 已实现行为

`repair/worker.py` 通过已有持久搜索租约、意图和独立 Replay Job 推进任务，不在控制器里调用 Agent 或工具。`agentgit repair-worker` 与既有 `agentgit worker` 是两个独立入口。每次推进有界处理最多四个在途意图；领取后核对未结算项，再按冻结 ordinal 派发。单点全部失败仍继续兼容的有序双点，不根据失败结果删去联合候选。

第一项为 Recorded 预检，消耗一次 screen 次数；`chain_valid` 只证明恢复链。筛选使用独立 Live/Hybrid Run 和固定验收器。未决计量或副作用保持完整预留，阻止扩展，不自动重发。取消先持久记录并阻止新意图，由研究 Worker 落实已派发 Job 的取消；确定未派发的意图才可按 `not_started` 释放预留。

发现通过候选后停止新增试验，排空所有已启动项再封存。仅在通过且零安全违规的已探索候选中，依次比较补丁数、规范字节变更范围、实际计量单位、费用和冻结 ordinal。`canonical-change-span/v1` 为删除最长共同前后缀后两侧剩余字节长度之和，组合逐项相加；它不是最小编辑距离，也不证明全局最优。所有未探索项、排除项和未确认范围保留在报告中。

停止报告由 `RepairSearchDecision` 约束，写入不可变 `repair_events` 和 CAS；短事务内重验租约、revision、取消标志和零在途项，然后原子封存。查询只读，不重算或覆盖历史决定。

| 状态 | 条件与范围 |
|---|---|
| `needs_confirmation` | 至少一个独立筛选通过；尚未运行 S10 确认、回归或逐项删除 |
| `no_solution_in_space` | 非空声明空间已经全部探索，每项均为确定的固定硬验收失败；只涵盖选入原子与冻结深度 |
| `budget_exhausted` | 任一准入维度不足；保存已有证据、未探索数量和具体原因，不推断无解 |
| `not_found` | 没有适用候选，或穷尽后仍有执行异常等非确定观测 |
| `needs_attention` | 恢复链失败、代码不兼容或实际量超过预留等，需要核查 |
| `waiting_reconciliation` | 尚有未知项；保持非终态和完整预留，核对完成后才继续 |
| `cancelled` | 用户取消后，全部已预留项得到明确结算；历史试验和取消请求保留 |

控制服务自身处理取消、代码不兼容及超额结算时，既有 revision 事件与 `stop_reason` 仍为权威记录；并非每种控制终态都会新增搜索算法决定。已封存决定随后被允许的控制操作接续时，原决定作为历史证据保留，不伪装为新的筛选结论。

## 新版 Mock 预算

旧 `bounded-templates/v1` 的 6 次模型、4,000 单 trial / 60,000 总单位保持不变。历史实测晚期 Plan 修复为 3 模型、2 工具、47,109 UTF-8 字节；正常完整路径为 11 模型、9 工具、94,103 字节。旧预算不足的事实见 [派发记录](S9-trial-dispatch.md)。

新增 `bounded-templates/mock-bytes-v2@<预算内容摘要>`，公共 Mock 入口默认生成该策略。单 trial 上限为 12 模型、12 工具、200,000 UTF-8 字节、60 秒，费用明确为零；每一维再与来源授权取较小值。总模型/工具为 30 倍单 trial，总字节为 15 倍，通常为 3,000,000。次数 30、14/6/6/4、15 分钟和默认并发一保持。确认与回归通常保护 2,000,000 字节，探索最多使用剩余 1,000,000；次数不保证用满。

任何预算参数变化都改变策略身份，不能把改变后的内容继续绑定原摘要。该策略只用于 Mock 字节计量，不能冒充供应商 Token；真实供应商须显式给出有限预算、费用和冻结价格表。本轮未进行付费供应商调用。

## 公共模板 API/CLI

公共请求只指定失败 Run、共同 base、冻结 screen 验收器、有限目标事件，以及可选的录制候选/预算/Hybrid。服务生成所有适用固定模板，不要求用户手写补丁 payload；共同起点以外的模型锚点、无权限的观测、任意 validator/权限/路径/计划补丁均不能通过该入口。

每个目标的模板不适用原因写入冻结 `template_skips`，超过原子上限的摘要写入排除列表。没有运行的空间不声称已经证明无解。观测候选仍须显式给出录制 ID，复用 S7 同项目、签名、参数、完整性、split 及 Hybrid 校验。

S7 干预拆成事务外准备和短事务发布，旧 `create` 入口保留。公共搜索先幂等发布已选入的不可变定义，再原子发布搜索、全部提案与控制任务；中途失败可以留有不可变定义，但没有研究执行意图或 Job。重试复用定义和原搜索，不能把一次请求扩展为多次执行。搜索原始请求的摘要直接保存于搜索账本，提交后丢失响应的重试不重新生成模板。单连接池也不在发布事务内申请第二连接。

接口、命令及请求示例见 [API.md](../API.md#有界修复搜索s9)。新增的是后端入口，桌面 Repair Lab 属于后续 S10；0.1.5 安装包不包含本轮新功能。

受控故障替身保留 Mock 协议，改变固定 Prompt 规则对来源文件路径的影响，并在联合例规划阶段省略 `write_sources`。替身源码摘要冻结在每个任务文本中，调用时复核。搜索器不读取标签，也不依据测试模式选择模板。单点/联合/永不修复/执行异常是独立合成工程 fixture，均为 `test_only`，不属于 S8 保留集或 S10 尚未建立的 30 例修复评估集。

原始包保存源码摘要、搜索/试验/Job/Replay 索引（适用包）、CAS 原始字节、来源及结果。五份受控替身包中，归档校验器所需 `reference_run_id` 明确为 `source_alias_for_archive_only`，与失败来源相同，只核验可达性，不表示另外运行了成功参考对照；`production-mock.json` 则保存实际成功来源对照及另建的失败分支。独立测试 Schema 在套件结束后销毁，归档 Run ID 不能作为业务 API 中仍存在的运行。

本轮不宣称稳定修复、`verified`、1-minimal 或全局最优，不写生产配置，不合并 main。S9 完整退出仍需逐项核对；S10、S11、S12-A/B/C/D 继续属于必选完整目标。独立 Windows 和 S8 人工审阅按用户授权保留待补。

# S9 原子试验派发与物理结算

日期：2026-10-24，分支 `codex/s9-repair`，基于 `df306f6`。[方案](../S9-repair-plan.md)和[持久台账](S9-ledger.md)继续保留完整阶段范围；本记录只覆盖真实试验通道，不替代自动搜索编排或 S9-T01–T07 整体退出。

## 行为与边界

1. `VersionService.prepare_fork/publish_fork` 与 `ReplayService.prepare/publish` 分离准备和发布。快照、请求和语料在发布前冻结；发布复核源分支的未决写入、安全起点和代码，不在持有发布连接时嵌套申请读取连接。S9 与既有管理 Replay 入口均可在单连接池下发布。
2. `RepairTrialService.dispatch` 在同一事务中提交研究 Job/Run、其输入、独立分支和试验归属；六路同一意图只产生一个 Job。创建 Job 后中断全部回滚，提交后丢失响应仍能查到原 Job。准备期间取消，发布前再次核对并拒绝新 Job；0018 的数据库触发器也拒绝无有效控制权的绑定。
3. Recorded 先核验原失败历史，完整证明只记 chain_valid。不调用模型/工具或其外部网络，不构造新的 Agent 工作区；逻辑失败状态保留，物理外部调用/费用为零。单独的实际墙钟期限可以收紧，不能改变原配置或放宽上限。
4. Live/Hybrid 试验使用现有 Worker。Hybrid policy 必须有当前项目精确提案归属；观测替换保持 synthetic/test_only，并从物理工具调用中剔除，不声称改写了外部世界。固定冻结验收器读真实产物判定，不能采信模型声称成功或一份可变报告字段。
5. 结算从耐久原始调用计量，绑定当前真实 Run；恢复后的 Run 不吞掉此前物理成本。没有计量、未知结果、预算/取消/安全停止分别保留，未知不记零。等待标记和观测快照不可变；多个未决项全部结算前不扩展新候选。晚到的旧未知观测不能覆盖已经提交的确定结果。超预留的已知实际量如实记录并转 needs_attention，不以预算截断隐藏开销。

## 真实证据范围

缺失 sources.json 的原失败 Run 被独立 Recorded 重算，恢复证明通过而逻辑状态仍为 failed，且禁止模型/工具调用的检查通过。随后自动 Plan 模板在另一个独立 Live Run 通过冻结验收；源失败 Run 的数据库行及主分支未改变。该筛选试验为 3 次 Mock 模型、2 次本地工具、47,109 个 Mock UTF-8 字节、零供应商费用；Recorded 不消耗这些物理调用。两项均只使用 screen 次数，未运行确认或回归。

Hybrid 例从包含只读录制的真实失败分支选择 read-5，引用显式已录制响应作为 test_only 观测。派发、policy 归属和物理计量经过真实 Worker；一项 synthetic 观测保留。该替换没有修复原计划遗漏，冻结验收仍失败，失败结果没有被筛掉或改成成功。

本轮按原实现计量使用显式的 200,000 单 trial / 6,000,000 总 Mock 单位，模型/工具仍为 6/12；**没有证明默认 4,000 单位足够**。当前例的实际量已超过默认单 trial 和预留后的探索余额，后续必须冻结新版 Mock 策略后重新验证默认效果。真实供应商请求及费用冒烟没有运行。

测试覆盖提交前回滚/提交后失去响应、已派发取消、单连接池六路并发、Frozen Oracle 与恢复作用域、结算幂等、多项未决、晚到旧观测、Recorded 实际期限收紧及旧 Fork/Replay/A-B/Hybrid 回归。首先修正了硬验收的 validation_failed 误归为执行异常；测试也取消了对 A/B Job 领取先后顺序的假定。最初失败 JUnit 保留，后续最终批次另存，不覆盖探索证据。

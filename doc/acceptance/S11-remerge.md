# S11 再次合并与交叉双父历史

日期：2026-10-28。分支 `codex/s11-merge`，基线 `266a059`。依据设计 5.5、5B.3 和实施方案 S11，延续[独立合并新任务](S11-merged-runs.md)。本增量补批准根作为语义 base、连续再次合并与真实交叉历史；30 组/基线、Merge Review、新包和完整阶段前置继续。

## 实现与边界

`ApprovedMergeOrigin` 保存批准 ID 与 Commit，不填写 Run 身份。作为 base 时，读取器核对不可变批准、候选和快照，沿前次三方来源重读实际调用、祖先、读取证明与当前效果状态；用于三方比较的私有投影仅含目标、计划及已核验记忆。合并根本身的用量为 `null`，执行标记为 `not_executed`。此前完成声明和用量继续保留在原 Commit，不递归相加，也不伪造零用量执行。两侧仍必须选择明确真实 Run。

每次读取请求共用独立缓存，最多 1000 个来源、32 层批准来源；循环、超限、错误批准或缺失证明拒绝。约束继续取工具交集和预算最小值，不构造模型配置或拼接调用轨迹。旧 Run 来源及旧请求省略新空字段，原规范编码保持不变；无需新迁移或依赖，当前仍为 `0026_merge_runs`、73 张产品表。

多个最佳共同祖先必须显式选择 `selected_base`。若非家族中的同一 Commit 有多个真实 Run，不能凭内容相同任选；新增可选 `selected_base_run_id`，必须同时指定 base，并由真实录制路径核验。API/CLI 共用提案 Schema，编辑、验证和批准重查同一选择，候选摘要继续绑定确切来源。

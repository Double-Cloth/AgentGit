## 已实现范围

- 新增 `0024_merge_proposals`，六张不可变表保存根提案、修订、验证、冲突、审阅票据及拒绝。复用旧 CAS 归属/历史不可变保护，补充同项目外键及串行修订/验证约束；当前产品表 70 张（不含 Alembic 版本表）。仅迁移独立 `test_<uuid>` Schema，业务库未迁移。
- 根提案固定两条不同分支、不同 HEAD、来源 Run、分支版本、选定共同祖先和冻结验收器。写入按仓库及稳定分支顺序加锁，活动写入者或来源失配拒绝；不通过修改原提案追随新 HEAD。
- 编辑保存完整定义，每版从原三方重建；最多 100 版，绑定前版 ref。支持完整 Plan、既有 source ID 的 base/ours/theirs/delete 选择及 `report.md`、`sources.json` 的有界文本替换/删除。权限、用量、效果、来源原文和验证结论不能上传覆盖。候选读取证明只保留当前选择的来源，原输入证据仍不可变。
- 显式验证重读来源、真实调用祖先、效果及固定验收输入，结果绑定确切修订、候选摘要、代码/锁和 HEAD/version。即使无内容变化的新版本候选摘要相同，也不能复用旧版验证或票据。
- 准备审阅须匹配当前通过的验证，并再算候选/结果；票据绑定操作者、提案、修订、验证及两个 HEAD。此操作只是准备审阅。拒绝记录当前确切修订并关闭追加路径，即使双分支已过时也可拒绝。
- HTTP/CLI 共用服务；写入具备 actor/route/key 幂等性。同键同内容重试返回原不可变收据，不使旧验证重新生效。查询不发布 CAS、不调用模型/工具、不排队 Job；票据支持每页 100 条的稳定游标和精确 ID 查询，包括已过时票据。

正式批准、双父 Commit 和 HEAD CAS 尚未实现，`approve` 路由不存在。Log/DAG/Fork/Diff/Recorded 的双父兼容、桌面 Merge Review、30 组及基线、新分发包仍待交付；未合并 main，未进入 S12。

25 个不同集成节点为当前范围，不与原型、迁移冒烟或历史通过数重复累加。实际流程覆盖：

1. 创建→验证→审阅准备→追加修订→旧验证失效→重新验证→新票据→重开→拒绝。相同候选摘要的空编辑也产生新修订，原键可查询旧收据。
2. 实际坏引文来源失败后，编辑候选双文件并重新硬验证；不把失败 Run 改为成功，不改来源。
3. 并发同键创建只保存一个根/首版；两个编辑仅一个成功；竞争拒绝只保存一个决定。
4. 验证后用测试夹具显式推进源 HEAD，审阅准备被拒绝、提案显示 stale；拒绝不进一步改变历史。夹具推进属于故意构造过时输入，单独于服务变更核对。
5. 在修订已写入但事务未提交处注入异常，根/版及引用全部回滚；原键重试仅发布一次。未引用的物理 CAS 文件可留待既有回收机制，不伪装成已提交记录。数据库禁止更新/删除证据行。
6. 真实 HTTP/CLI 贯通及身份、项目、参数边界，关闭模型/工具/排队入口后继续可用；只读查询再禁止 CAS put，旧票据分页及精确读取仍通过，未知票据和未实现批准返回 404。
7. 测试 Schema 的 24→23→24 往返签名一致，正常模式拒绝降级；历史迁移未改写。

六组各由真实 Mock 原任务与两个实际 Live 分支准备。最终归档合计 78 次模型、54 次工具、736,578 个 Mock UTF-8 字节，实际费用 0；这些是输入准备调用，合并服务本身零新调用/Job/Run。共保存 6 提案、10 修订、7 验证、1 冲突、4 票据和 4 拒绝。原始重审从 CAS 域 hash、归属、请求摘要、修订链，到真实调用意图祖先、来源原文、预算交集、硬规则、票据和拒绝绑定逐项重算；外部调用与 Job 和输入归档一致。

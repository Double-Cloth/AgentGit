# S5 复合 Recorded 来源批次

本记录证明 Recorded 可作为再次回放的来源，完整 S5 验收现已汇总于 [S5.md](S5.md)。其他可信核对与接管封存已完成专项；S6、必选 S11/S12 的最终交付仍在主链中。

## 机制

`ProjectionReader` 按来源 Run 找到自身冻结 Job 和恢复根，校验不可变请求、配置、证明连续顺序、目标 Run 归属、父边、状态/环境、事件 SQL 索引与 CAS 清单。范围仍限定在指定 Run 的 base 和自身检查点；恢复来源可用自身 base，不能凭相同状态摘要冒用其他 Run 的证明。

每层映射必须连续覆盖底层选定路径。原始录制照常校验 occurrence、请求/响应、执行证据和产物；证明齐全但原始数据缺失也明确失败。递归读取全链共享 64 MiB 预算，读取和纯重算均限制 32 层，循环和超限不回退 Live。

纯 Runtime 重算最底层历史，回调把重算结果逐层与直接来源检查点比较，验证状态、产物和逻辑事件；新证明绑定直接来源 Commit。连续恢复边界保留为零调用恢复，非零执行范围通过 Runtime 调用计数验证。配置与预算基线沿用冻结环境，物理 Run ID 和耗时保持独立。

`0012_replay_source_index` 增加 jobs(repository_id, origin_run_id) 索引；开发库已升级，旧迁移快照不改。隔离迁移往返和正式降级保护沿用项目约定。

## 验证范围

- 完整、部分、零长度、包含恢复点的范围，以及三层嵌套。
- 来源 Recorded 自身已恢复、复合 Job 崩溃恢复；期限不重置，前缀不重复发布。
- 暂停/恢复、取消、到期；原分支及来源证明保持不变。
- Live 独立预算历史经 Recorded 后再次 Recorded，累计用量和预算基线一致。
- 原始响应缺失、映射/快照/逻辑事件错配，以及其他 Run 的证明移植均失败；状态与逻辑事件按规范编码精确比较，不能把布尔值 true 与整数 1 当成相同证据。
- 全链累计大小与纯重算深度边界，不按层重置读取预算。
- 真 Shell/Python 来源两层 Recorded：禁止构造真实模型/工具/工作区/容器客户端和宿主进程，完整时摘要一致；删除底层产物时失败；无新增执行记录。

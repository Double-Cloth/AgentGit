# S10 原始归档安全与预算计数

2026-10-27，运行 release 保持 `0f981aba918904366022c05373484be572cf36b96a5042d05304e6200a3524de`。本记录补充开发二十例的原始计数；保留集仍在执行，不将部分结果升级为完整三十例或 D2 验收。

`repair_benchmark_safety.py` 在逐例完整响应/硬验收审计之后，核对同一原始清单/容器及审计收据的摘要。每次实际调用的 provider、effect、意图身份和请求引用必须匹配既有固定 Mock/三工具；录制恢复和 Hybrid 虚拟观测单列。读取真实 `artifact_write` 参数，非法相对路径须有 failed、完整错误、零响应字节，不能只凭 failed 字段判为安全。全部产物索引路径再按冻结跨平台策略核对。

各方法的最终用量须无活动预留，模型/工具/Mock 字节/费用、总次数及各阶段次数均在原预算内；没有使用末尾已不存在的确认报告替代缩减停止状态。搜索绑定的验收器及失败来源与空间绑定一致，正式批准和保存实验记录为空。墙钟由既有执行层约束，统计保留实际耗时；本补充检查不把这些计数扩大成宿主全局 I/O 监控或所有潜在权限问题的证明。

计数包括每例共享准备和全部五方法，准备 Run 不重复分摊为各方法成本；与开发全量 11,000 模型、8,899 工具一致。60 次是请求拒绝数，不是成功写入或主机外部动作。搜索绑定核验与权限契约共同提供验收器不可改的证据，完整三十例还须用相同条件重新汇总。

八项反例测试通过：仅失败标签、缺错误、非零响应和不完整拒绝均不能冒充安全；超工具/字节/阶段预算以及活动未知预留均拒绝。报告为 `S10-safety-accounting-contract-v1.xml`。这八项是分析边界测试，不计研究任务或修复成功。

忽略目录 `S10-evaluation-v1/analysis/train-safety-v2.json` 的 SHA256 为 `d644425d1b9ffb6fc369d4a5e9480dd73bf31b8f8b84b6950f687392ea85cc75`，绑定每例完整原始审计收据、代码身份和迁移补充来源核验。v1 计数相同，v2 仅补充明确预算字段与墙钟/宿主监控范围，旧版本保留。迁移来源证据不倒填为原 release 的运行时检查，具体缺项见[冻结说明](S10-evaluation-freeze.md)。

# S8 只读行为证据基础增量

2026-10-24，依据设计文档 5B.2、实施方案 S8 第 1 步及 [S8 方案](../S8-diagnosis-plan.md)。这是后端基础增量，S8 尚未整体验收。独立 Windows 用户安装/升级/卸载及 S6/D1 原生交叉复核按用户指示暂缓；S7 前置待补，不合并 main。

## 已实现

- 严格类型化 Run/seq/数据库事件 ID、DAG 节点、依赖依据、证据缺口和对齐输出。拒绝循环、重复和错误端点；长链采用非递归校验。
- 只读核对当前项目 Run 的连续事件索引、完整检查点路径、Commit/事件清单、CAS 归属与摘要、调用意图/规范请求、录制观测及错误。无归属和越权引用在读取对应对象前拒绝，损坏内容报错；已归属事件正文/响应丢失则保留未核验与缺口。
- 显式 caused_by 和同 occurrence 调用边；计划/决策边须由已核验快照、匹配的模型状态请求或工具参数以及唯一调用观测支持，不从相邻事件推导。来源 Run 未展开的依赖保留 outside_trace，不伪造全图。
- 有共同版本祖先时按逻辑/调用身份及已对齐依赖确定匹配，签名、规范请求、观测、错误和依赖分别呈现变化。重复身份只有唯一内容或依赖上下文才消歧，不用时间、到达顺序或数据库 ID 选配。首个可见分歧是 DAG 上的最小前沿，可包含并行差异，不称为根因。
- Management、认证 API 和 CLI 共用读取服务：`GET /runs/{id}/behavioral-trace`、`GET /behavioral-diff`、`agentgit behavioral-trace/behavioral-diff`。运行中显示捕获范围，证据不完整；无共同祖先明确不对齐。没有新增迁移、依赖、后台 Job、桌面桥接或 capability 宣称。
- 每侧最多 10,000 事件、30,000 去重边/缺口，当前 Run 内容缓存累计 64 MiB，单图及合并报告各 8 MiB，重复匹配比较 200,000 次；祖先核验另受既有版本服务深度和单对象上限约束。超过限制直接 output_limit，不输出完整性含糊的前缀。

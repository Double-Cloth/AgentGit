# S10-T01 三原子真实删除用例

2026-10-26，分支 `codex/s10-repair`，接续 `7caed9a`。本增量新增工程行为用例和后续字段缩减方案，生产源码/迁移/依赖未改，仍为 `source-sha256:6d5cc94ae6ecc54c24a90f9de0a68fe556d1f9daf421fb56cea20c860a71961f`。S10、D2 及后续必选范围保持未完成。

## 执行范围

`test_repair_three_atom_reduction.py` 直接连接通用缩减协议和既有 S7 配对实验/普通 Worker。公共 S9 搜索仍只枚举单点、双点；持久 study 仍从其已通过候选建立，没有新增三点搜索或人工种子 API。此处证明 S10-T01 的通用协议在真实独立 Run 中正确删除及重新测试，不把工程 fixture 当作 30 例研究数据。

三个原子为：

- A：已有引用核验 Prompt 模板。
- B：在已有计划中补入缺少的 `sources.json` 生成节点。
- C：将最后一次只读观测替换为同一完整录制的相同响应，明确作为冗余原子；有 C 时检查 `synthetic` 和精确干预 ID，无 C 时检查 `recorded`。它不构成观测伪修复或外部工具世界改善的效果证据。

原失败来源位于最后一次只读调用前的安全模型检查点。全程使用同一冻结来源、验收器、任务、语料、时钟、权限和有序补丁；适配器源码摘要在任何试验前写入任务输入并由实际模型核对。固定只读观测不计实际工具调用，模型仍新调用，历史前缀也不计为新模型调用。

## 实际结果

每轮由 S7 创建独立的“当前候选对照”和“删除后候选”两个 Job。初始空候选失败、A+B+C 通过；之后实际删除结果为：

| 当前候选 | 删除 | 删除后结果 |
|---|---|---|
| A+B+C | A | 失败 |
| A+B+C | B | 失败 |
| A+B+C | C | 通过，接受 A+B |
| A+B | A | 失败，重新执行 |
| A+B | B | 失败，重新执行 |

五次删除对应五个不同实际 Job/Run，前置对照也全部通过。总计六轮配对、12 个不同 Job/Run，无旧结果充数，源分支和来源状态保持。通用协议得到 `one_minimal_under_fixture`，范围仅为该确定性条件和原子删除语法；`field_reduction=not_run`、`global_optimum=false`。最终候选仍为 A+B，所有已见配对结果和 Run 都纳入锁的排除范围，未打开或执行确认池。

S7 的试验主键为实验/组/索引复合键，测试以其唯一 Job UUID 关联缩减证据，并核对真实复合键归属；没有虚构另一张持久 trial 表。协议的每个状态前缀、实际结果、最终摘要与候选锁均登记 CAS，保存所有派发前准入决定。

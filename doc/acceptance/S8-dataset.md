## 规格与冻结顺序

`21455b4` 在任何排序实现或调参之前冻结 `tests/fixtures/diagnosis/v1/cases.json`、D01–D12 开发集/D13–D20 保留集及注入器源码。冻结清单 `release.json` 校验原始规格、注入器摘要及逐项划分；原始工作区字节与该 Git Commit 的 Blob 已核对一致，使用仓库 LF 换行。后续不能修改同一版本的故障或划分来提高已知指标。

20 例覆盖错误检索、空响应、Schema 变化、确定性超时替身、计划遗漏/循环、冲突记忆、过期/未来来源、模型协议和报告证据错误。每例先执行独立正常研究 Run，再从首个检查点 Fork 故障分支，调用实际 Gateway、Runtime、PostgreSQL 和 CAS；故障分支有独立 Task、Run 和工作区，来源分支不变。语料时钟固定，重规划上限固定为零，故障不靠后续重试掩盖；采用三个基础工具，不调用外部供应商、外网或容器。超时是明确标记的错误替身，不声称实测了网络超时可靠性。

全部标签是代理提出的 `agent_proposed/pending_human`，注入点、首个可见异常与拟修复决策分开记录。Corpus 注入绑定冻结 input_ref，其余标签解析为唯一的真实 Run/seq/整数事件 ID；修复决策仍是待检验提案，不保证干预能修复。完整 [人工审阅清单](../S8-dataset-review.md)已准备，并已请求用户稍后反馈；未收到反馈的样例保持待审阅，不视为默认同意。未来审阅记录绑定本规格摘要及真实反馈来源，另存附加记录。

## 实际验证与归档

最终 **32 项通过，189.91s，无失败或跳过**：20 项参数化真实数据库构造、1 项清单完整性检查和 11 项冻结/标签隔离/离线证据契约检查。每例均生成并核对一个成功参考 Run、一个具有预定错误及硬断言的故障 Run，全部 20 例保留；两侧行为图均无证据缺口，未提交前缀不冒充完整图。

最终检查增加：缺样例、划分改变、未知操作、伪造人工批准均拒绝；规格、注入器或冻结划分摘要不符要求新版本；改变标签、期望错误和分割不改变注入响应；离线对象原字节、域隔离摘要、长度和所属项目逐项核验，损坏/跨项目证据拒绝。

每例保存 `<ID>.json` 的两侧行为图、录制注入收据、实际用量和拟议标签引用，并保存 `<ID>-evidence.json` 的有界原始 CAS 内容（base64）与事件、检查点、调用及所属索引。测试 schema 结束后清理，证据包支持脱离已销毁测试库复核原字节；不会自动导入业务库，也不表示原 Run 仍可通过业务 API 查询。对象每例最多 4,000 项、16 MiB 原字节，各索引每类最多 20,000 行，超限拒绝归档。

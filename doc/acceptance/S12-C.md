## 四角色固定契约

`core/collaboration.py` 声明 `offline-four-role-research/v1` / `agentgit-collaboration/v1`。Supervisor、Researcher、Verifier、Writer 各有明确权限与独立 BudgetLimits；固定 collect→verify→write，write 同时依赖 collect，拒绝未知角色、重复权限、动态依赖/重规划、任意代码及 Shell/Python 权限。RoleBinding 要求四个不同 agent_run_id 与 task_id，但此处仅为输入约束，尚未在数据库创建这些实体。

消息固定项目/协作、message_id、实际 sender/receiver Run、接收任务、correlation、kind、payload_ref 与父事件地址（Run/Commit/seq/payload）。十条允许路由在全部六十种不同角色对/消息类型组合中核对。跨项目/协作、未绑定 Run、接收任务不符、父事件不是发送方、额外 actor/未知 kind、伪造关联与非整数序号均拒绝。纯路由核对不能证明事件实际存在、调用者身份或 payload 可见性；后续服务必须从耐久记录逐项授权。

DeliveryLedger 固定程序及绑定摘要，最多 32 条唯一消息；同 ID 同完整输入是无新增候选的幂等结果，同 ID 换 payload/接收方冲突。收到重复消息前仍核对其余账本，不能让首项重放掩盖后续外项目记录。共享路径按角色权限分别核对：Researcher/Verifier 的 evidence.json、Verifier 的 verification.json、Writer 的 report.md/sources.json。候选更新要求精确安全整数版本和相同程序/项目/协作/路径，保留发布角色的父事件地址；Verifier 更新后 Researcher 的旧版本候选拒绝。该函数不是数据库并发锁，也不读取或授权 CAS 字节。

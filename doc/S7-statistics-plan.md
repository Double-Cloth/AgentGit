# S7 分组统计与桌面接线方案

接在 [Hybrid 持久运行](acceptance/S7-hybrid-runtime.md)之后完成实施方案 S7 第 5–6 步。继续使用既有实验查询、验收器和调用账本；不增加新迁移、外部统计服务或前端依赖。

## 统计来源与契约

1. 保持当前 `groups` 的计数结构，新增独立 `statistics` 对象，按 A/B 返回试验总数、passed/failed/incomplete 数、硬断言通过情况及样本范围。成功率分母使用所有预定 trial，未完成不当作通过；另列已完成可评估样本数，避免排除失败或未完成造成选择偏差。既有验收器在缺产物或 Schema 错误时会短路，当前只能对明确的整体硬断言结果计数；不能把错误列表未出现某项解释为该规则已通过。
2. 所有数据取自当前真实 trial/冻结 assessment 和物理调用账本；不能从用户提交的成功标签生成指标。查询是各 Job 的有界一致投影，声明为查询时状态，不承诺跨所有运行的瞬时原子快照。
3. AGJSON-v1 禁浮点，均值和样本方差使用精确分数，携带分子/分母、单位和样本数；以整数计算 `mean=sum/n`、`sample_variance=(n*sum_squares-sum*sum)/(n*(n-1))` 并约分。单样本方差未知，不能写成零。固定 Mock 的零方差只描述给定 fixture 下的确定性指标，不推断供应商模型波动。
4. Mock UTF-8 字节、供应商输入/输出 Token、混合单位分别保留。逻辑累计用量与共同预算基线之后的增量分开；物理调用不能把 Hybrid 观测或恢复消费计入。
5. 费用区分价格表估计、已知费用、预留和未知/未结算，不将缺失计量或未知动作记为零费用。Mock 的零收费须明确标示来源；真实模型保留 currency/pricebook。时延为实际墙钟毫秒，固定 fixture 的重跑不要求墙钟一致。
6. 每种指标列有效/缺失/未完成样本数；不能将取消前的部分用量与完整成功样本混为同一完整执行均值。允许另列截至查询时的累计消耗。

## 接线与验证

先实现纯聚合函数及有意义的边界用例：全未完成、全失败、成功/失败混合、单样本、未知计量、不同 usage_kind、整数精确方差和极大整数。随后以真实 PostgreSQL 对照 Live/Hybrid 的每 trial 明细，覆盖恢复前后不重复计费与重复 fixture 的确定性指标。

API/CLI 使用同一统计投影，补充一致性与项目边界测试。桌面沿用 Branch Experiment 页面和现有身份/固定 IPC/API 桥，在 manifest/分组/trial 列表显示来源、预算、模式、test_only、synthetic 来源和未知费用；取消/暂停/恢复仍使用当前 Run 的版本及既有控制端点。实现 UI 前重新读取根目录 DESIGN.md 和相关 React/UI 技能。

最后在实际 Electron 流程中验证提交、查看十次试验、取消/恢复、错误和状态刷新；不得把 API 单元测试替代桌面交互验收。S6 延后的原生/独立环境要求仍须在最终交付前补齐。

# MCP 有界任务与恢复接入

接续 `17c02af` 首增量，在现有 Job、Run、History、ApprovalService 和 RecordedAdapter 上接通实际任务，不改变研究任务的五工具配置。沿用实施方案第 1.2 节的工程授权和全部正式门槛。

首批实际任务明确为一次固定 MCP 工具调用：冻结绑定、参数、响应/墙钟/工具次数预算，输出 `mcp-result.json`。没有 LLM、任意代码或 stdio 执行。操作者通过后端可信登记构造绑定；渲染进程不能提交任意网络地址或凭据。参数先验证和检查凭据字段，凭据仍从 Worker 环境注入。

现有 jobs 增加明确的 `mcp_run` 类型，复用原租约、心跳、fencing、控制、分支写锁和幂等键。只迁移隔离测试 Schema；正式业务迁移由操作者准备。本次不新增任务表或队列。MCP Job 的不可变 payload 是该有界任务输入，Run 不伪装成三框架研究 Task。旧 research_run 路径保持原契约；读取 MCP 轨迹需识别其状态种类。

实际执行先提交空结果/零用量初始检查点，固定调用前检查点与 once 身份，再经现有调用网关完成审批、意图和原始结果。恢复优先消费完整耐久结果；已有意图但结果未知时不创建客户端或重发，保留待核对。批准和普通 resume 不改变原绑定/参数。排队取消零调用；调用期间的取消等待记录结果或未知诊断，关闭传输不能冒充撤销远端写入。墙钟和工具次数都受原预算约束。

Recorded 显式选择同项目原 Run 的初始/最终检查点及真实成功录制，在独立来源分支运行，不创建 MCP 客户端。验证固定 binding/请求/签名/原始对象及源码/锁，不支持缺失录制的 Live 回退。比较声明的逻辑投影：输入和结果引用、逻辑用量、终态及产物原字节；新 Run 身份、本次实际尝试/遥测不作为逻辑相等条件。实际 Recorded 网络请求必须为零。

Worker 在创建任何客户端前独立核对 Run 模式与不可变 replay 字段，成功发布前及完成检查点恢复时核对来源最终逻辑投影；原始产物同时固定路径、摘要和媒体类型。既有桌面审批列表补齐所展示 Run 的版本号，按钮使用该版本提交，过期版本仍由后端拒绝。

验证覆盖实际 Worker 子进程、写审批、同键/版本竞争、队列取消、暂停恢复、完成结果后进程中断、意图后未知恢复、原始 CAS/事件/产物重算、Recorded/缺依赖与跨项目拒绝。补充只读 API/桌面轨迹可见性及可运行演示，保持 S2/S4/S5/S6/S11 兼容；尚未完成时继续记在 [S12-A 工程记录](acceptance/S12-A.md)，不进入 B 或宣告 D3。

# S10 Repair Lab 桌面实施

依据设计 5B.4、界面信息架构及实施方案 S10。用户已授权按既定方案继续工程实现；S6 独立 Windows 环境和 S8 人工标签稍后补验。视觉沿用根 DESIGN.md 与现有四页，采用 Operate 模式；不改品牌、字体或配色，不将工程验收冒充 D2 研究效果。

## 业务路径

1. 新增按需加载的 Repair Lab 页面；运行、时间线或静态候选只交接明确的 Run/检查点/事件，不将排序当作因果。显示当前完整模板降级及 S8 未达标限制。
2. 操作者核对失败来源、模型决策前起点、冻结 screen 验收器、有限事件和预算，提前选择四个不同回归任务的安全来源。使用原子准备入口一次发布搜索及十张采样票据；不通过界面跨两个 POST 与 Worker 抢先领取竞争。缺来源或预算不满足时不给出可用搜索动作。
3. 展示候选、淘汰/未知试验、预算保留与实际计量、停止原因；显式开始缩减。显示原子、字段与复查的确切范围，不夸大为全局最小。最终候选锁定后才显式开启原 suite，再查询六次确认及四项回归。
4. 展示封存报告、实际样本数、Wilson 区间、安全、适用任务/环境、原始证据及小样本限制。筛选通过不代表已验证，未执行票据不算样本，缺失/未知不能显示为零费用。
5. 显式生成精确建议，完整展示 before/after、Prompt/Plan 和补丁顺序。读取审阅票据后才允许最终决定；票据与建议摘要、来源配置和项目版本一并显示。版本冲突须重新核对建议并显式获取新票据。正式批准只创建新配置，保存实验仅保存定义，两者不启动任务。
6. 观测替换永久显示 test_only 与作用范围，禁用正式配置采纳并给出原因；确认失败或未完成不得批准或保存为合格实验。仍可审阅和拒绝，不能看失败结果后用原池换候选。

## 状态、重试与重开

所有修改动作防双击，冻结参数和幂等键；未知响应只允许原键确认，明确拒绝才可重新定义请求。轮询、切页、断连恢复及窗口重开只 GET，不自动 POST；保留最后确认结果及其刷新错误。重开从项目搜索列表和只读 workflow 发现已有 suite/study/proposal，不能用“重新创建”充当查询；关联投影和当前页面已实现。

优先沿用 `useRead/useAction`、既有连接工作区与响应上限、主进程固定路由、sender/frame/项目边界和安全文本渲染。Review 通过固定字段桥接；不暴露任意 HTTP 路径、执行指令或宿主资源。新页面在桌面、1024、768 和窄窗口下保留可用主操作；表格可在容器内横向滚动，页面不整体溢出。焦点与状态文字沿用现有可读规范。

- 升级基线为已归档 `.agentgit/packages/desktop-0.1.7/AgentGitSetup.exe`，摘要 `8ca050f02fafc3d41f67eb6ecbc1978bdb78da655a03bb431675e93920e4d912`，四件套已再次实际读取核对。不要用out中已覆盖的同名Setup冒充旧包；旧包对应关系见0.1.7记录。两次安装使用同一预置后端版本和数据，避免把后端代码变更混入桌面升级测试。

- 测试只需离线 Mock，不配置真实供应商密钥。桌面预置与 API 匹配的身份令牌，禁止把它放入命令行、截图、清单或归档。

## 环境门槛

需要另一个 Windows x64 用户会话或专用 Windows x64 虚拟机。该会话没有项目源码和前端构建用 Node/npm/Vite，可复制交付包；后端服务与业务数据独立于应用安装目录，禁用外网后仍可完成离线流程。禁止以修改当前用户的 profile 目录冒充独立 Windows 用户。

当前自动化进程未提升管理员权限，未取得另一个用户会话，也未发现可直接使用的测试 VM；本机真实安装/升级/卸载已在 Codex MSIX 的 LocalCache 重定向上下文通过，并不等同于这个独立用户条件。不自动创建账户、修改系统权限或索取明文凭据。待环境可用后，记录系统版本、用户隔离方式、包摘要、后端版本/迁移和字体离线可用性，继续执行以下步骤。

## 执行与保存证据

同时记录该独立环境的 Windows 原生 100% / 150% / 200% 显示缩放、窗口宽度和字体表现；此前 Chromium 强制缩放仅作为渲染证据。整机禁止外网且不配置供应商 Key 后复验离线任务和确定性检查，不能仅凭 Mock 名称填写“禁止外网已验证”。

1. 在独立用户中先安装已核验的0.1.7基线Setup，为第6步准备旧版本。记录退出结果、安装位置、开始菜单／快捷方式及实际版本，确认无需Node或开发服务器；实际信任阻断单列。如果直接测试0.1.8首次安装，须另行准备升级基线，不能把升级项填为通过。

## 已准备的输入

- 安装程序 `desktop/out/make/squirrel.windows/x64/AgentGitSetup.exe`，以及同目录 `AgentGit-0.1.5-full.nupkg` / `RELEASES`；当前四个分发文件另存 `.agentgit/packages/desktop-0.1.5/`。
- 便携包 `desktop/out/make/zip/win32/x64/AgentGit-win32-x64-0.1.5.zip`。安装程序和 ZIP 的摘要见新候选记录，均未签名；不将本机可运行等同于分发信任验证。
- 升级基线为已归档 `.agentgit/packages/desktop-0.1.4/AgentGitSetup.exe`，摘要 `ef29ae8a1d072b41724198928787b91642738597b3d749d8239f2566b93f627e`。不要用 out 目录中已被新版本覆盖的同名 Setup 冒充旧包；旧包对应关系见 0.1.4 清单。两次安装使用同一预置后端版本和数据，避免把后端代码变更混入桌面升级测试。
- 真实后端由独立操作者按 [DEVELOPMENT.md](DEVELOPMENT.md) 准备 PostgreSQL、已迁移的数据根、API、Worker 和固定 Docker 镜像。前端用户可连接同机回环 API，Worker 继续使用已准备的身份与数据目录；不会要求桌面自行安装后端。
- 测试只需离线 Mock，不配置真实供应商密钥。桌面预置与 API 匹配的身份令牌，禁止把它放入命令行、截图、清单或归档。

## 环境门槛

需要另一个 Windows x64 用户会话或专用 Windows x64 虚拟机。该会话没有项目源码和前端构建用 Node/npm/Vite，可复制交付包；后端服务与业务数据独立于应用安装目录，禁用外网后仍可完成离线流程。禁止以修改当前用户的 profile 目录冒充独立 Windows 用户。

当前自动化进程未提升管理员权限，未取得另一个用户会话，也未发现可直接使用的测试 VM；本机真实安装/升级/卸载已在 Codex MSIX 的 LocalCache 重定向上下文通过，并不等同于这个独立用户条件。不自动创建账户、修改系统权限或索取明文凭据。待环境可用后，记录系统版本、用户隔离方式、包摘要、后端版本/迁移和字体离线可用性，继续执行以下步骤。

## 执行与保存证据

同时记录该独立环境的 Windows 原生 100% / 150% / 200% 显示缩放、窗口宽度和字体表现；此前 Chromium 强制缩放仅作为渲染证据。整机禁止外网且不配置供应商 Key 后复验离线任务和确定性检查，不能仅凭 Mock 名称填写“禁止外网已验证”。

补充 S6-T11 交叉复核：在独立测试环境准备依赖的过程中，保留 API 未启动、数据库未就绪、Worker 实际停止、Docker 不可达和固定镜像尚未导入时的 UI/任务结果。只对测试自有依赖安排这些场景，不删除共享镜像；记录真实状态，不能把本机故障注入的镜像 404 直接填为独立环境实测。

1. 在独立用户中先安装已核验的 0.1.4 基线 Setup，为第 6 步覆盖升级准备旧版本。记录退出结果、安装位置、开始菜单/快捷方式及实际版本，确认无需 Node 或开发服务器；不绕过系统信任拦截，把实际阻断单列。如果改为直接测试 0.1.5 首次安装，须另行准备升级基线，不能把升级项填为通过。
2. 连接已准备的本机 API，创建离线五工具任务并完成；在 Timeline 查看 Python/Shell 命令、日志、退出码、清理和文件。记录 Run/Job/Commit 和产物摘要。
3. 从安全检查点 Fork；Recorded 覆盖完整来源范围，验证实际调用/网络/执行容器为 0；A/B Live 写同名不同字节文件，Diff 展示两个摘要。来源历史和 main 不变，容器清理确认。
4. 从产物的“另存为”打开实际 Windows 原生对话框，保存到新临时文件，确认与所选版本原字节一致。另测取消无写入；不用替换 showSaveDialog 返回值代替此项。
5. 执行中关闭/重开桌面，重复启动和界面崩溃恢复后查询同一任务；后端继续，不新增提交。断连/重连后游标补齐并与 API 终态一致。
6. 保持后端代码、依赖、数据和身份不变，用 0.1.5 Setup 覆盖 0.1.4 基线，核对安装日志和实际版本变化，重新连接原项目和已完成任务；确认桌面不自动迁移 Schema，不丢产物或业务数据。不能只运行两次同版本 Setup 就宣布升级成功。
7. 退出并卸载 0.1.5。卸载前后比较已记录数据库对象、来源指纹、CAS/产物原字节、API/Worker/Docker 服务状态。业务数据仍完整；重装同摘要 0.1.5 后可重新连接查询，并单独记录该次安装结果。只清理明确属于此次安装的程序，不删除业务数据。
8. 在同一独立环境解压 ZIP，从无源码/Node 的目录运行四页核心流程，并记录相同离线约束。安装程序与 ZIP 各自保留证据，不能互相替代。

将实际结果、失败原因、运行 ID、安装/升级/卸载日志摘要与截图位置写入 `doc/acceptance/`。不记录凭据，不把未执行步骤写成通过。S6-T06 真实供应商冒烟另外明确启用并确认实际预算，独立安装验收不隐含允许真实费用。

# S11 Merge Review 桌面实施

依据设计 5B.3、实施方案 S11-T04–T06 和[合并计划](S11-merge-plan.md)。三十组[后端评估](S11-merge-report.md)已归档；本计划接通真实 Electron 审阅与更新包，不据此前工程结果宣布阶段完整退出。

## 交付顺序

1. 补齐项目内只读提案发现、完整共同祖先查询及能力标志。列表仅返回有界元数据，详情仍重核 CAS；多基点由操作者显式选择，同摘要多 Run 继续要求明确来源，不由页面排序决定。
2. 增加固定业务 IPC：发现/创建/读取、完整修订、验证、准备本人审阅、历史票据、精确批准/拒绝及批准后独立分支/新任务。主进程校验项目、标识、版号、摘要、受限字段和有界 JSON；不提供任意 HTTP、路径、Node 或 Shell 通道。
3. 在现有导航增加“合并审阅”。沿用 DESIGN 的暖画布、现有字体/对比度和组件，呈现来源 base/ours/theirs、冲突、候选状态/产物和验证。普通编辑提供来源选择及两个文件；计划 JSON 放在开发者可理解的明确编辑区域，不能编辑权限、用量、效果或验证结论。
4. 完整替换编辑、验证和精确票据按版本绑定。编辑后旧验证和票据失效；批准只使用本次显式准备、完整匹配的本人票据及候选，历史票据只读。断连保留草稿和未知请求的原键/原体，恢复或重开只查询，不自动 POST；用户选择原键确认后才重试。
5. 批准后显示双父和独立合并状态。继续执行须显式输入配置版本、预算和独立分支，经既有 merge-fork/merge-run 入口；不继承完成、轨迹或授权，也不因批准自动排队。来源变化、拒绝、未知和不支持类型明确呈现。
6. 按既有 Electron/Playwright 配置分别执行桥接与 HTTP fixture、真实 PostgreSQL/API/Worker/CAS 联调，最后生成更新 Windows 包并在包内复验。S6/S8 人工/原生暂缓项和 S11 人工预期保持待补。

## 交互与验证

目标路径：打开合并审阅 → 发现/创建提案 → 核对三方原文与来源 → 显式选择或完整编辑 → 保存新修订 → 重新验证 → 本人精确审阅 → 批准/拒绝 → 只读重开；批准后新任务为单独显式流程。

重开列表的“未关闭”仅表示没有批准/拒绝决定，不表示来源当前或候选已验证，打开详情后才显示实时 stale/validated 状态。提案、历史票据分页均有界且拒绝跨项目游标；已批准根不是已完成 Run，base 的 null 用量显示“未执行”，不能显示为零成本执行。

沿用 `useRead` 的退出/切换取消 GET、`useAction` 的双击保护和已确认工作区断连保留。编辑草稿与服务器候选分别管理，草稿未保存时禁止准备票据/批准；结果未知时不得换键自动补发。源 HEAD、当前修订、validation ref、ticket ref 和候选摘要共同控制动作可用性，后端仍在事务内重查。

测试覆盖：非法字段/路径/项目、缺能力、异步数据与参数变化、旧票据、双击/原键、未知确认、拒绝/过期、实际双父历史、明确 Recorded 入口、只读重开及新任务初始化。尺寸覆盖现有桌面宽度与最窄受支持窗口，键盘焦点和长证据文本；截图与运行日志用独立前缀，HTTP fixture 不充当真实后端证据。

Browser 插件未提供，使用项目既有 Playwright/Electron 验证真实主进程/preload/renderer，不安装新依赖。结构和样式继承现有操作界面，本任务没有视觉体系变更；完成后按 impeccable 只做一次集中视觉检查与必要的一次确认，不开放无界美化循环。

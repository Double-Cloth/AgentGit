# S12 工程推进次序提案（待用户选择）

当前仍依[实施方案](AgentGit_实施方案_v1.0.0.md)执行：S11 完整验收前不开始 S12。用户此前允许暂缓独立 Windows/人工项目、先推进 S11 工程；本文件把可能的下一步明确列出，尚未扩展该例外，也未开始 S12 产品代码或调整正式退出条件。

若用户明确选择继续工程，建议将“验收待补时可继续工程”的次序调整扩展到下列四项，仍按 A→B→C→D 顺序实施：

| 顺序 | 已约定范围 | 本机技术核对 |
|---|---|---|
| S12-A MCP | 可信本地 Server 的 tools/list、Schema 缓存和调用；先固定协议版本、登记端点及权限范围 | Schema 变化、超时/错误、越界地址/重定向、凭据脱敏、远端提示不覆盖本地效果/审批；Recorded 零实际网络请求 |
| S12-B LangGraph | 固定框架版本和一类明确图结构的事件/checkpoint 映射 | 支持范围内暂停、恢复、Fork 及隔离；不支持节点明确拒绝，不宣称任意图无损恢复 |
| S12-C 同进程四角色 | Supervisor、Researcher、Verifier、Writer，各自 Run/预算/权限及消息因果边 | 子任务失败/取消、重复消息、共享产物竞争、私有上下文和跨 Agent 数据隔离 |
| S12-D A2A | C 的本机协作稳定后，固定官方版本，在本机独立进程接能力、任务、消息、产物和身份 | 未授权、重复、断连、过期、取消及未知写入；不盲目重发，Recorded 零真实请求 |

每项接入已有事件/状态/版本、预算、审批、CAS 和恢复契约；以 Mock LLM、可信本地服务和隔离测试库验证，无公网账号或付费模型依赖。四组 fixtures/演示、锁定版本、逐项验收记录、S12-T01–T07、核心兼容性回归、最终桌面包和 D3 汇总均保留为必选。现有研究 release、预期、成绩和用户暂缓项目不重写；SDK/协议的具体版本与实现方案在该项正式工程开始时核对官方资料后冻结。

当前 S11 仍在 `codex/s11-merge` 归档本机工程和 0.1.7 候选结果。若获明确选择，先提交当前增量，再从该完整状态建立 `codex/` 开发分支推进 A；不合入 main、不将人工/原生待补标为通过，也不据单个适配器完成宣布 D3。完整交付依然必须满足 S0–S11 与 S12 四项的全部正式门槛。

若用户选择先补齐 S11 正式验收，则保持既定顺序；环境、S8 标签及[三十例人工预期](S11-benchmark-plan.md)准备就绪后按原清单续验，不自动创建 Windows 账户或索取密码。

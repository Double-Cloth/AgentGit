# S10 精确提案与人工审阅实施边界

依据设计 5B.4 与实施方案 S10-T05/T06。本文记录实际确认之后的下一增量方案，尚未实现审批或配置采纳；Repair Lab、30 例/四基线及 S11/S12 的必选范围保持。

## 现有实现事实

`ResearchService.create_config` 在项目行锁内按 `agent_configs.version` 全项目递增；Live/Hybrid 试验也会创建私有配置版本。目前没有独立的“正在使用的 Agent 配置头”，Task 始终绑定明确 config ID。不能把最大版本对应的试验预算当成正式来源配置，也不能假装批准已更新一个不存在的活动指针。

`AgentConfig` 已支持 Prompt、模型、权限和预算，没有可采纳的 Plan 模板字段；Plan 当前属于运行状态和干预结果。只保存审批记录而不让新任务使用被批准的 Plan，不能算作完成 Plan 采纳。

## 提案与版本

新增独立的最终修复建议记录，引用 study、最终候选锁、封存确认摘要、原始结果和源 S9 提案；不能把 S9 的筛选提案 ID 当作已确认建议。一个 study 只生成一份精确内容建议，变更内容需新评估和新身份。

提案同时冻结来源 config ID/version/body ref 和审查时的项目配置版本计数器。批准基于明确来源配置创建一个新版本，并在同一项目行锁下检查计数器仍为预期值；审查后任何新配置版本（包括新试验配置）都会保守地使旧审查失效。新增版本不改原配置、不改已有 Task 的绑定，也不启动 Run/Job 或外部工具。界面明确显示来源版本与新版本，不把新版本创建解释为已经自动切换现有任务。

精确 Diff 展示正式配置的 before/after：Prompt 原文、Plan 模板完整 DAG，以及原子/字段缩减范围。使用来源配置的原授权和预算，不复制验证 trial 收紧后的限制，不允许修改模型、工具、执行策略、验收器、任务 split 或其他未声明字段。附上候选锁、验证环境、适用任务、成本、最小性范围与不确定项。

## Plan 与观测补丁

Plan 采纳复用现有 `Plan` 契约，在 `AgentConfig` 增加可省略的有界 Plan 模板字段；无该字段时保留原配置编码。新任务从模板建立版本化计划和明确来源事件，不继承旧 Run 的完成节点、记忆、产物、授权或副作用。直接运行与持久 Worker 使用同一初始化路径；Live/Recorded 对计划、预算和事件的验证仍须通过。该路径必须由真实新任务证明，不仅检查新配置 JSON 中存在一个字段。

含 `TOOL_RESPONSE_PATCH` 的建议禁止正式配置采纳。允许的“保存为实验”只保存精确实验定义/引用与审阅记录，不调用会排队执行 Job 的 `ExperimentService.submit`。真正运行实验须另有明确提交动作，再核对当前代码、验收器、项目与授权；历史观测不因为审批而获得真实世界有效性。

## 审阅事务与核对

批准/拒绝绑定建议摘要、候选锁、封存验证摘要、来源配置及预期版本、操作者和决定；同键同参返回原决定，改决定/改参数冲突。CAS 对象和决定不可修改，配置创建与决定保存原子提交，断连重试不能生成第二个版本。字段被替换、配置版本推进、跨项目引用、缺确认/回归、安全失败和观测补丁正式采纳都应明确拒绝。

首先实现 API/CLI 与真实 PostgreSQL/新任务验证；审批期间禁止 Model/Tool Adapter 调用，并检查 Jobs/Runs/原配置/分支均不变。再按根 `DESIGN.md` 接入 Electron Repair Lab、精确 Diff、审阅原键重试、版本冲突、断连重开与包内验收。测试操作者仅用于隔离 Schema；本机业务配置不会因开发测试被自动采纳。

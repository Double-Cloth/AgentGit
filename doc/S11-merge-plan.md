## 交付顺序

1. 实现有界共同祖先与只读产物候选。复用 `StateSnapshot.artifacts`、CAS BLOB、路径校验、AGJSON 和现有 `ResearchReport`；先支持 UTF-8 Markdown 章节及 `sources.json` 的明确 Schema。未知类型明确拒绝，不能把通用 JSON 递归拼接作为语义合并。
2. 增加 Fact、TaskNode、Constraint 和效果审计投影。现有研究状态的事实对应 `(framework, dimension)`，证据对应 `Evidence.source.id`，计划对应 `PlanNode.key`；合并后重新检查正文摘要/引用、时间、DAG、完成前置、预算及权限。调用轨迹和未知外部动作不能拼接为新的可执行轨迹，容器/进程不合并。
3. 用新迁移持久化提案、冲突、修订、验证和精确审阅。绑定项目、base、两分支 HEAD/version、候选摘要、验证器与政策；编辑后旧验证/审批失效。API/CLI 共用服务，修改带身份、幂等键及预期版本。
4. 在批准事务中锁定双分支并重查上述绑定，创建稳定顺序 `(ours, theirs)` 的双父 Commit，仅 CAS 更新目标 HEAD；拒绝、过期、竞争失败不更新历史。合并不启动 Run 或执行工具。
5. 升级 Log/DAG/Fork/Diff/恢复和显式 Recorded 路径兼容。多个最佳共同祖先必须显式选择其中之一，不凭路径距离任选，也不递归构造虚拟 base。
6. 按 DESIGN.md 接入 Merge Review、受限 IPC、候选编辑/重新验证、精确批准/拒绝及重开只读；生成新 Windows 候选。冻结 10 无冲突、10 事实冲突、10 计划/约束冲突样例、人工预期和基线，执行 T01–T06 后逐项归档。

## 首增量的有限产物协议

共同祖先内核最多读取 10,000 个不同 Commit，每节点至多两个不同父；缺失、非法摘要、环或超限明确失败。返回全部最佳共同祖先，按摘要排序仅为了稳定展示；多个时返回 `ambiguous_merge_base` 及完整候选集合，等待显式选择。读取器从同项目索引读取并核对 manifest，不改变既有单父写入约束。

Markdown 只支持严格 UTF-8、以列首 `## ` 分隔的唯一二级标题及其前言；代码围栏内的标题保留为正文。不解释嵌套章节或任意 Markdown AST；重复/空标题、未闭合围栏、已有章节重排明确不支持。原章节按 base 顺序保留，新章节按标题稳定排序。章节是完整原字节块，不逐行调和双侧修改。相同修改或单侧修改/删除可选取；删除与编辑、同章不同编辑返回 `WRITE_WRITE`，冲突时不输出可用文件。

`sources.json` 仅接受项目 `ResearchReport` v1：固定 fixture、evaluation_time 和 frameworks；claims 以 `(framework, dimension)`、sources 以 `source.id` 对齐并整体三方选择，保留完整 Evidence，重复身份拒绝。事实双侧异改报 `FACT_CONTRADICTION`，时间不一致报 `TEMPORAL_MISMATCH`，来源异改保守报冲突；不拆开同一条证据拼接字段。当前保留 base 中仍存在实体的顺序，新实体按稳定身份追加，再通过 Schema；这样不改变现有 Markdown 渲染器依赖的事实顺序（首增量原身份排序保留为历史实现）。原始缺失与 JSON null、bool 与 int 均按项目严格编码区分。

每个输入文件上限 1 MiB、Markdown 上限 1,000 章节。候选保留三方 BLOB 摘要作为证据；只读预览从 `HistoryService.restore` 与 CAS 获取真实字节，重算 BLOB 域摘要。即使产物无冲突，也始终标记结构化状态、任务/来源核验和人工审批待办，不能据此落地 Merge Commit。首增量不提供批准、双父写入或外部执行权限。

## 结构化状态与验证协议

状态候选使用独立的 `merged_research_state/v1` Schema，保存 goal、按 `PlanNode.key` 三方选择并重新验证的计划、按 `Evidence.source.id` 对齐的工作记忆、三方原用量、完成声明、来源读取证明和效果审计。它不是 `AgentState`，不复制 messages、pending_tool、执行容器、审批或活动状态；后续启动任务必须显式建立新 Run。已完成节点只能保留原节点和依赖语义，完成声明仅审计，不能代替新 Run 的执行。

当前 Fact 支持既有 `SourceFact` 的文本值及固定三类维度，以 `(framework, dimension)` 对齐；值按原文比较，不从自然语言推断单位转换，不接受未知数值/单位 Schema。正文、引文、有效区间、采集时间和完整来源须与冻结语料一致；同一主体/维度的相异值阻断。事实证明还必须匹配同项目、明确来源 Run/Commit 的实际 source_read occurrence、请求和响应，不能只采信 working_memory 或报告中自称的来源。

约束采用三方工具授权的交集及每项预算上限的最小值，不合并为更大权限；固定执行策略不一致阻断。检查 DAG、完成前置、计划所需工具、完整计划的最低工具/模型调用量、文件数及单文件大小。历史用量按来源分列，不相加为新 Run 预算，也不声称静态检查保证未来 Token/费用/墙钟足够；真实新 Run 仍由既有预算与审批执行层约束。

效果仅留审计；未知、未决或未清理的执行阻断。来源 trace 中的写入及检查点祖先上未决意图均需检查，不能只看状态 status。分支新增的不可逆/非幂等外部动作须作为 EFFECT_CONFLICT 审阅，不能选择来源后自动重发。既有本地 artifact_write 的已知完成记录可审计；容器执行需要已有清理证据，本增量不合并容器状态。

完整只读预览绑定三方来源、真实 state/environment、当前源码和锁、固定验收器、候选状态及全部候选产物摘要。使用冻结验收器的输入/语料执行既有 report 硬规则，但单独标为合并产物验证，不伪造 completed Run 或 FrozenAssessment；通过后仍须人工审批。所有修改后的候选必须重新计算和验证，不能复用旧结果。

完整验证目前只覆盖 `report.md` 和 `sources.json`，其他 Markdown 仍只能做首增量的未验证产物预览；未知文件不会因未被报告验收器检查而自动成为“已验证”内容。调用证明除 occurrence/签名/请求/响应外，还必须证明调用意图的前检查点属于选定 Commit 的祖先；相同字节不代表同一条执行轨迹，分叉后原 Run 的读取不能进入新分支证明。

## 耐久提案、修订与审阅协议

提案固定 ours/theirs 的项目内分支名、源 Run、预期 HEAD/version、选定 base 及冻结验收器。创建、编辑、验证和准备审阅在同一仓库锁内按稳定名称锁定双分支，禁止活动写入者或版本不符；拒绝只记录操作者看到的确切当前修订，不要求过时分支恢复到旧 HEAD。两条分支名和 HEAD 必须不同，避免将相同 Commit 伪装成双父合并。

所有根提案、完整编辑定义、候选修订、验证、冲突索引、审阅票据和拒绝决定使用新迁移、同项目 FK、CAS 归属及不可变表。修订从同一三方原始输入重新构造，提交的是完整编辑定义，不能把旧补丁盲目叠到新来源；每版绑定前版 ref，按提案串行追加，创建后最多 100 版。幂等身份包括 route/actor/key，跨请求重用键拒绝；未知提交结果按原键查询，不重新创建第二条记录。

编辑范围为完整 Plan、已有来源的 base/ours/theirs/delete 选择及既有双文件的 ArtifactPatch；不能提交 MergedResearchState、来源正文、验证结论、效果记录、用量、权限或预算。编辑后所有旧验证/票据立即过时；重新验证须重读原始调用、祖先、效果与冻结输入。每次验证记录确切修订 ref、候选摘要、代码/锁、HEAD/version 与硬规则结果；准备审阅时再计算一次，拒绝复用已变化的来源证据。源码升级使原冻结验收器不兼容时保留旧提案只读，需要显式创建新验收器与新提案，不能静默升级旧记录。

本增量提供持久提案、修订、验证、审阅准备与拒绝的 API/CLI，均不创建 Run、外部动作或 Commit。正式批准必须与后续双父创建/CAS 同一事务实现，不先记录“批准成功”再等待其他阶段写历史。该后续能力、历史兼容、桌面、三十组与分发均仍是必选交付。

重开查询读取已保存的修订/验证/拒绝和审阅票据，不创建 CAS 或后台任务。票据列表按 `(created_at, id)` 倒序，每页最多 100 条；使用返回的 `reviews_next_cursor` 读取旧页，也可按同项目提案/票据 ID 精确读取。旧票据保留，但 `current` 只表示当前版本绑定尚匹配，`requires_recheck` 始终为 true，不能作为批准许可。

## 正式批准与双父历史

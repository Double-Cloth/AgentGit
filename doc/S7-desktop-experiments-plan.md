# S7 桌面实验接线方案

这是后端统计与固定 IPC 之后的接线方案，目标为实施方案 S7 第 6 步；不新增导航页面、前端依赖或状态框架，不重做既有视觉体系。2026-10-24 源码视图和本机流程已接通，事实与剩余包/总门禁见 [S7 桌面增量](acceptance/S7-desktop.md)，不将本方案预期直接算作验收。

## 入口与任务路径

沿用 Branch Experiment，保留现有 Fork/Recorded/单次 Live 行为，在同页增加受控 A/B 区域，由独立组件维护实验状态。现有奶油底色、标题字体、可读主按钮、表单与表格样式继续作为视觉依据；这是 Operate 场景，以明确操作、状态和来源为先。

主路径为：选择来源 Run 和安全检查点 → 显式冻结验收器 → 设置 A/B 条件、重复次数、共同预算及 Live/Hybrid 模式 → 提交一次 → 查询 manifest、分组统计和 trial → 打开时间线或控制未完成运行。另提供输入既有 Experiment UUID 的只读查询入口，重新连接/打开页面不能创建新的动作。

## 契约与交互

1. 新固定桥接在 `shared/bridge.ts`、`preload/index.ts`、`main/routes.ts` 提供验收器、实验、干预和实验列表共八个操作。验收器和干预用已有端点；不开放 renderer 自定 URL、认证头或对象路径。补充后端实验能力标记，旧后端仅禁用新增实验入口，保留原分支功能。
2. 来源输入预填已有选中 Run/Commit，异步来源核对完成才允许冻结/提交；切换来源不能沿用旧配置、旧 validator 或在途查询结果。候选检查点是否安全、是否属于该 Run 始终由提交时后端重新核对。
3. 验收器通过独立显式动作冻结，显示规则、固定评估时间、split 与摘要。原历史/旧代码验收器不兼容时如实提示，不重新解释成通过或零成功率；不能自动改 verifier。当前 API 的历史验收兼容边界须在 UI 接线时处理并测试。
4. 默认各五次，次数 1–10；A/B 允许固定 Prompt/计划或既有有序干预 ID，不能改模型、权限、验收器、split 或各组预算。常用表单与高级合法 JSON 分开，原始定义可展开审阅。外部模型必须显式确认本次 USD 上限，沿用已有整数金额解析和授权上限检查。
5. Hybrid 通过只读事件上下文取得来源调用 ID，显示完整请求/签名和范围终点；选择受控只读工具和 stop/fixture 策略。工具响应补丁须绑定已选调用及既有 test_only 干预，synthetic/模拟来源显著标为试验结果，不能提供“应用正式配置”动作。
6. 提交前固定请求与幂等键，防双击。未知提交结果保留原请求/原键，先查询或用原键重试；不能换键自动排队。清空/开始另一实验须由新的显式操作触发。
7. 查询按当前项目和 Experiment ID 隔离；轮询退出时清理，保留已确认数据和明确的刷新错误，不把断连变成零值。每个 trial 显示初始/当前 Run、Job、状态、判定和来源；当前 Run 变化后时间线/控制必须使用新 ID。
8. 暂停/取消/恢复沿用 `getRun/controlRun`。点击时重新取得当前版本，提交仍固定本次动作与键；状态冲突需重新核对，未知结果不得自动新建动作。不得重发 outcome_unknown 的模型或副作用调用。

## 统计呈现

成功数与全部预定样本的成功率为主要摘要，已验收样本数与未完成数并列。所有消耗和完整执行分布分开；每种指标显示样本覆盖与单位。Mock 字节不标为 Token，供应商 Token、已知估价、未知费用与预留分列，账单未知不能显示为零。

分数和大整数均以字符串到有界 BigInt 格式化，不先转 Number 或用浮点金额乘除。解析拒绝异常长/无效分母，并保留原始精确值查看入口。均值或方差没有样本时显示未知；格式化近似值须有明确标记。固定 fixture 的重复结果不宣称模型泛化稳定或因果。

使用紧凑分组与 trial 表格、展开明细和既有时间线按钮，不为每个指标增加装饰卡片。长中文、UUID、摘要和 JSON 在自身容器换行/滚动；保持键盘焦点、表格标题和控件名称。

## 验证与交付

先验证合法/越界输入、幂等重试、来源切换和精确格式化，再通过真实 Electron 验证提交、十个 trial、查询既有实验、取消/恢复、断连/重开与无新增 POST。真实 API/独立 PostgreSQL/Worker 复验 Live 与 Hybrid，保留 synthetic、miss 和未知结果的真实状态，至少复核一条五工具实际容器链。

按 768/1024/1440 内容宽度及既有补充 360 检查布局，批量截图检查一次、集中修正后复核；遵循 DESIGN.md 和已读取 UI/React 技能。不将 HTTP fixture 当作真实任务，不用旧桌面包证明新视图完成。视图与本机验收完成后再构建新的 Windows 候选，S6 延后的独立用户和原生专项仍保留。
